Security

Last updated: September 14, 2026

Security-first beta. Sensitive controls are kept private, connector tokens stay server-side and paid checkout remains disabled until the full launch path is tested.

Access controls

Private workspace records use authenticated access and row-level database controls. Roles are separated so management actions can be restricted to authorized workspace members.

Private files

Secure workspace uploads use private storage rather than public URLs. File access is scoped through authenticated workflows and private object paths.

Secrets and connectors

OAuth tokens and connector secrets are stored server-side. Public client code does not contain provider client secrets. Connector status is not reported as connected until a real provider authorization completes.

Webhooks

Outgoing webhooks are signed, retried, rate-limited by processing logic and validate destinations. Redirects are blocked and private/local destination ranges are rejected to reduce SSRF risk.

Vendor portal

External vendor links are random, expiring and one-time. Only token hashes are stored in the database, and old links can be revoked.

Auditability

ExpenseLeak records security-relevant and workflow events where practical, including connector syncs, vendor submissions and operational actions.

Data minimization

Only upload business information needed for spend and procurement workflows. Do not submit passwords, full card numbers, government IDs, medical records or unnecessary sensitive personal information.

Vulnerability reporting

If you believe you found a security issue, use the Support & Data Requests page and choose Security. Do not include live secrets or exploit another user’s data while reporting an issue.

Limitations

No online system can guarantee absolute security. Security controls continue to be reviewed as the beta expands and before commercial launch.
